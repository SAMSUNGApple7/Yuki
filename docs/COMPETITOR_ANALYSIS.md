## 3 · 逐个深拆

### 3.1 Flomo · 卡片笔记
- **核心**：高频次、低门槛的卡片式记录
- **优势**：交互极简、移动端体验顶级、社区生态强
- **不足**：纯被动工具，不解决「执行」与「复盘」问题，AI 几乎缺席
- **可借鉴**：极简交互范式、对中文用户的字号 / 行高优化

### 3.2 滴答清单 · 任务管理
- **核心**：日历 + 任务 + 提醒
- **优势**：功能完整、跨平台、提醒能力强
- **不足**：任务来源都是用户手动输入，不解决「拆解」问题；周报是简单统计，无洞察；AI 集成浅（仅"语音转任务"等表层场景）
- **可借鉴**：任务卡片信息密度、四象限优先级 UI

### 3.3 Notion AI · 文档 Copilot
- **核心**：在文档场景内嵌 AI 写作 / 总结
- **优势**：文档与任务统一、AI 调用门槛低
- **不足**：AI 是「按钮」，不是「角色」；用户必须手动驱动 AI；学习曲线陡
- **可借鉴**：AI 与原生 UI 的融合方式、属性视图设计

### 3.4 MetaGPT · 多智能体框架
- **核心**：模拟软件公司的多角色协作完成开发任务
- **优势**：多 Agent 范式验证、角色专业化设计
- **不足**：纯 B 端开发场景、命令行体验、无 C 端可用产品
- **可借鉴**：✦✦✦ Agent 角色分工 + 共享 Memory 协议 + 任务流转设计

## 5 · 差异化策略

### 5.1 "我们做什么、我们不做什么"

**Yuki 做**：
- 三 Agent 协作 / 闭环成长 / 透明 Memory / 学习场景特化

**Yuki 不做（至少 v1.0 内不做）**：
- 通用笔记（让位给 Flomo）
- 团队协作 / 项目管理（让位给 Notion / Lark）
- 通用对话（让位给 ChatGPT）
- 时间块日历（v0.3 后再做）

| **Yuki** | **"Three minds, one growth. 让每一天的成长被看见。"** |

## 6 · 战略建议

1. **不和滴答清单正面竞争**：避开「待办列表」叙事，主打「成长闭环」
2. **借力 MetaGPT 范式**：在 PR 中明确提及"将 Multi-Agent 范式带入 C 端"，吸引技术早期用户
3. **借鉴 Flomo 极简哲学**：移动端首屏不超过 5 个元素
4. **学 Notion 的"工具就是身份"**：让用户在朋友圈晒 Yuki 的周报，形成传播
