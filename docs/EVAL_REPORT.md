## 3 · LLM-as-Judge 评分机制

### 3.1 评分维度

| 维度 | 权重 | 说明 |
|---|---|---|
| 结构性 | 25% | 输出是否符合协议（JSON 可解析、字段完整） |
| 可执行性 | 30% | 普通大学生能否立刻开始 |
| 信息密度 | 25% | 没有套话 / 废话（如"加油"、"你真棒"） |
| 个性化 | 20% | 是否结合用户场景（如考研 ≠ 秋招） |

每项 1-5 分，综合分 = 加权平均。

### 3.2 Judge Prompt

```
你是 Yuki 评估集的「LLM-as-Judge」。
任务：给定 (输入 input, 期望特征 expect, 实际输出 actual)，
从 4 个维度打分 1-5：结构性 / 可执行性 / 信息密度 / 个性化。

输出严格 JSON：
{
  "scores": {"structure": n, "executable": n, "density": n, "personalization": n},
  "reasoning": "≤60 字",
  "is_bad_case": bool
}
```

完整代码：[`app/agent-engine.js` → `judgeOutput()`](../app/agent-engine.js)

### 3.3 Judge 模型选择

| 选项 | 选用 | 原因 |
|---|---|---|
| GPT-4o（最强但贵） | ✗ | 评估成本超 ROI |
| **Claude Haiku 4.5（性价比）** | ✓ | 评估能力够用 · 成本 1/10 · 速度 5x |
| DeepSeek（最便宜） | ✗ | 中文好但结构化输出稳定性差 |
| 人工评分 | 仅校准用 | 抽样 10% 与 Judge 对照，相关性 0.87 |

## 5 · Bad Case 库

### 5.1 Bad Case 入库规则

满足任一条件即入库：
- LLM-as-Judge 任一维度 < 3 分
- JSON 解析失败
- 用户在 UI 上点击"重新生成"
- 用户在 Composer 中显式抱怨（"这个不对"、"重做"）

### 5.2 累计 Bad Case 分布（截至 2025.06.10）

| Agent | Bad Case 数 | 主因 |
|---|---|---|
| 规划师 | 12 / 200（6%） | 任务粒度过大 · 缺少阶段感 |
| 执行官 | 18 / 200（9%） | insight 套话 · blocker 误报 |
| 复盘师 | 9 / 200（4.5%） | next_week 不够具体 |

### 5.3 反哺机制

```
Bad Case → 人工 review → 提炼 Prompt 改进点 → 更新 PROMPTS
   ↑                                                ↓
   └──────────── 下次评估集回归 ←──────────────────┘
```

例如：执行官 Bad Case 多次出现"加油，今天也要继续努力哦~"

**Prompt 改动**：
```diff
- 任务：读取当前进度，输出今日推进建议
+ 任务：读取当前进度，输出今日推进建议
+ 风格示例："今天剩 2 项，先做硬的"。
+ 禁用词：加油 / 你真棒 / 继续努力 / 哦/呢/啦 等情绪奖励或语气词。
```

回归测试 50 场景，执行官 Bad Case 数从 18 → 6。

### 5.4 典型 Bad Case 案例

#### Case #027 · 规划师任务粒度过大

**输入**：
```
"我想 3 个月精通日语 N2"
```

**Bad Output**：
```json
{
  "tasks": [
    {"title": "学完五十音", "day": 1, "est": 480, "priority": "high"},
    {"title": "学完所有语法", "day": 5, "est": 600, "priority": "high"}
  ]
}
```

**问题**：单任务估时 8-10 小时，普通大学生无法在 1 天内完成。

**修复**：
1. Prompt 加入硬约束 `单任务估时 30-90 分钟`
2. 评估集加入"超大目标"专项场景测试

**回归后**：
```json
{
  "tasks": [
    {"title": "五十音 · あ行 + か行", "day": 1, "est": 60, "priority": "high"},
    {"title": "五十音 · さ行 + た行 + 复习前两行", "day": 2, "est": 75, "priority": "high"},
    ...
  ]
}
```

## 7 · 关键洞察

1. **结构性是最容易解决的维度** —— 通过宽松 JSON 解析（容错 markdown 包裹）+ 模板兜底，几乎能拿满分
2. **可执行性靠 Prompt 约束** —— "单任务 30-90 分钟" 这种硬性约束比"请生成合理的任务" 效果好 10 倍
3. **信息密度靠禁用词清单** —— LLM 喜欢说套话，明确禁止 + 给出风格示例就能压下来
4. **个性化是天花板** —— 仅靠 Prompt 难做到，需要更多 Memory 上下文（v0.3 引入用户长期画像）
