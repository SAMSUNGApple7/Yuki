| 测试轮次 | **2 轮** |

---

## 1 · 测试目标

不验证"用户喜不喜欢"，验证 4 个具体可用性指标：

1. **任务可达性**：用户在没有引导的情况下能否完成黄金路径
2. **概念理解度**：用户能否在 60 秒内说清"三 Agent"分别做什么
3. **学习曲线**：第 1 次到第 3 次使用，效率是否显著提升
4. **错误恢复**：当 AI 输出不符合预期，用户能否找到修正路径

## 3 · 第 1 轮测试（v0.8 · 2025.05.05）

### 3.1 关键发现

| 任务 | 成功率 | 平均耗时 | 主要卡点 |
|---|---|---|---|
| T1 · 30s 内说清 Yuki 是什么 | 3/8 (37.5%) | — | 大部分人误以为是"普通待办" |
| T2 · 创建目标 | 8/8 (100%) | 67s | ✓ |
| T3 · 勾选任务 | 8/8 (100%) | 14s | ✓ |
| T4 · 打开复盘 | 5/8 (62.5%) | 41s | 3 人没找到，把"复盘"理解成"历史" |
| T5 · 生成本周复盘 | 4/8 (50%) | 95s | 4 人不知道"为什么要生成"——以为应该已经有 |
| T6 · 重新拆解 | 2/8 (25%) | 超时 | **6 人找不到入口** ← 严重问题 |
| T7 · 切换深色模式 | 6/8 (75%) | 38s | 入口太隐藏 |

### 3.2 SUS（系统可用性量表）得分

**v0.8 SUS = 71.3 / 100**（业界 68 为可接受门槛）

### 3.3 关键负面反馈

| 反馈 | 频次 | 影响 |
|---|---|---|
| "三 Agent 的颜色太鲜艳，像玩具" | 6 | 设计语言问题 |
| "拆出来的任务我想改但不知道怎么改" | 6 | 严重交互缺失 |
| "复盘按钮怎么没有红点提示？" | 4 | 缺少状态反馈 |
| "我以为是另一个 ChatGPT" | 3 | 定位传递不清 |

## 4 · v0.8 → v0.9 改动

基于第 1 轮反馈，做了 4 项关键改动：

### 改动 1 · Hero 文案直击差异化

```diff
- "Yuki 让你的成长更轻松"
+ "Three minds, one growth. 让每一天的成长被看见。"
+ Hero 下方加副标题: "由三个独立 AI Agent 协作完成 定目标 → 执行 → 复盘 的闭环"
```

### 改动 2 · 任务编辑可用

```diff
+ 拆解结果展示后，每条任务卡：
+   - 点击可编辑文本
+   - 右侧"+/-"调整估时
+   - 长按拖动调整顺序
+   - 顶部"重新拆解"明显按钮
```

### 改动 3 · 复盘语义重命名

```diff
- 顶部菜单: 复盘
+ 顶部菜单: 复盘  · 当本周未生成时显示"本周待复盘" + 暖金点提示
```

### 改动 4 · 三 Agent 颜色重做

```diff
- 规划师 #FFD700 / 执行官 #FF4444 / 复盘师 #00CC88
+ 规划师 oklch(0.66 0.12 70) / 执行官 oklch(0.55 0.10 245) / 复盘师 oklch(0.60 0.08 175)
```

## 8 · 方法论沉淀

### 8.1 学到的经验

1. **"用户看不懂"通常不是文案问题，是定位问题** —— 改 "Hero 文案 + 副标题 + 视频" 三件套，不是改某一句话
2. **"找不到入口"在 SUS 上比"用不爽"扣分多** —— 优先解决可达性
3. **3 版迭代足够覆盖 80% 严重问题** —— 后续问题更多是"喜好"层级

### 8.2 不再做的事

1. ❌ "做大改后再统一测试" —— 改动越多，归因越难
2. ❌ "8 人一轮测试"不够 —— 5 人即可发现 80% 问题（Nielsen 原则）
3. ❌ 只看 SUS 数字 —— 必须配合 think-aloud 录像复盘
