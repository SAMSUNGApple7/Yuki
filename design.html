DESIGN 01 / ARCHITECTURE

Bad Case 列表 · 用于驱动迭代

场景 评分 用户反馈 改进方向
目标拆解 ★★☆☆☆ "任务粒度过细，3 天目标拆成 15 个子任务太繁琐" 增加颗粒度调节器（粗略 / 适中 / 细致）
复盘报告 ★★★☆☆ "周报像流水账，缺少深度洞察" 优化复盘师 Prompt，强制要求洞察段落
任务追踪 ★★★☆☆ "提醒频率过高，有打扰感" 增加智能免打扰 + 用户偏好学习
Agent 协作 ★★☆☆☆ "规划师和执行官有重复推荐" 优化 Memory 状态同步，加 lock 机制
用户引导 ★★★☆☆ "首次使用不知道如何开始" 增加引导式 Onboarding · 3 步上手
设计意图：构建评估集量化产品价值，用 Bad Case 驱动迭代 — 这是 PM 数据思维的核心。多 Agent 方案较单 Agent 基线在任务完成率上有显著提升，验证架构可行性。
